# 文字起こしがうまくいかないとき

2026 年 9 月の 1 週間、実際の会議録音 10 本で試して分かったことをまとめています。
数値の詳細は [ENGINE_BENCHMARK.md](ENGINE_BENCHMARK.md) にありますが、
**普段はこの 1 枚だけ読めば足ります。**

---

## 何が起きるか

**同じ 1 行が何十回も繰り返され、その間に話されていた内容が消えます。**

```
エンディングを作ってみます。
エンディングを作ってみます。
エンディングを作ってみます。
   … これが 70 行続く
```

会議の内容とまったく関係のない文が出てきます。鉄道や年号の話、料理の手順、
「私は、私のビデオを紹介します。」のような決まり文句が典型です。

**やっかいなのは、エラーが出ないこと。** 画面には `完了:` と表示され、ファイルも普通に
できあがります。中を読むまで気づけません。だから**自動で警告を出す**ようにしてあります。

---

## どのくらい起きるか

10 分ごとに区切った 28 区間のうち、**12 区間**で起きていました。おおよそ 4 割です。

会議の**最初の 10 分に集中しています**。接続待ちや雑談が入っている時間帯です。

---

## 原因として分かったこと

**人が聞いても聞き取りづらい区間で起きます。**

繰り返しが出た区間の音声を実際に聴いてもらったところ、元々かなり聞き取りづらい録音でした。
音が小さいわけではありません（むしろ問題のなかった区間より大きいくらいでした）。
声の帯域のエネルギーも雑音の量も、うまくいった区間とほぼ同じです。

**元の音に情報が入っていないものは、後からどう処理しても出てきません。**
これが 1 週間かけて得た結論です。

---

## 効かなかったこと

**全部試して、全部外れました。** 同じ順番でもう一度試さないための記録です。

| 試したこと | 結果 |
| --- | --- |
| 大きいモデルを使う（`large-v3-turbo-q5_0`） | **悪化。** 繰り返しが 70 回 → 123 回に増えた |
| 音量をそろえる（`loudnorm`） | **悪化。** 文字数が 2,546 → 753 に減った |
| 参加者名のヒント（初期プロンプト）を外す | 変わらず。繰り返しは出続けた |
| 参加者名を毎回付け直す（`carry-initial-prompt`） | 悪化。ヒントの文自体が 42 回繰り返された |
| 候補を増やす（`best-of`） | 変わらず。処理時間は同じで文字数はむしろ減った |
| 無音を飛ばす設定のしきい値を下げる（`vad-threshold`） | 変わらず |
| 無音の割合から起きる区間を予測する | **できない。** 無音が 0% の区間でも 67 回の繰り返しが出た |
| 音量から起きる区間を予測する | **できない。** 相関はあるが境界が引けない |

---

## 効いたこと

### 1. 自動の警告

区間ごとに 3 つを数えて、おかしければ警告します。ファイルは必ず書き出すので、
**直すかどうかは人が決めます。**

| 見ているもの | 警告が出る条件 |
| --- | --- |
| 同じ行が何回続いたか | 5 回以上（ただし「はい。」のような 8 文字以下の相槌は数えません） |
| 1 秒あたり何文字拾えたか | 2.5 文字未満（普通は 4〜6 文字です） |
| 結果が空か | 空なら必ず |

**2 つとも必要です。** 短い 1 文が 67 回繰り返された区間は、文字数だけ見ると正常値でした。
逆に、無音を飛ばす設定で内容が 8 割消えた区間は、繰り返しの回数だけ見ると完璧でした。
**片方だけでは片方向を見逃します。**

### 2. 警告が出た区間の直し方

**区間ごとにやり直せます。** `part_NNN.txt` を消してもう一度実行すると、その区間だけ
処理し直され、他はそのまま使われます。10 分の区間で 2〜3 分です。

1. まず `--vad` を付けて流し直す（無音を飛ばす設定）
2. **文字数を必ず見比べる**
3. 減っていたら元に戻す

**`--vad` は諸刃です。** 繰り返しを 3 回消した実績がある一方、正常だった区間の内容を
8 割削ったこともあります。どちらに転ぶかは事前に分かりません。

### 3. 手で詰める

繰り返しが 1 か所にまとまっているなら、**その行を 1 行に詰めるのが最善のこともあります。**

| 同じ 10 分 | 文字数 |
| --- | --- |
| そのまま（20 行の繰り返しを含む） | 3,434 |
| `--vad` を使う | 1,692 |
| **繰り返しを 1 行に詰める** | **2,864** |

`--vad` は繰り返しと一緒に中身も削ります。**同じ録音の中でも区間ごとに勝者が変わる**ので、
区間単位で見比べてください。

---

## これから効くのは録音のしかた

ソフト側でできることはやり尽くしました。効果が大きい順です。

| | 内容 |
| --- | --- |
| **1. Web 会議はアプリ側で録音する** | Teams / Zoom の録音機能や PC の音声出力を録る。スピーカーから出た音を IC レコーダーで拾い直すのが一番不利 |
| **2. 録音開始を会議開始に合わせる** | 繰り返しは最初の 10 分に集中している。接続待ちや雑談から始まると、そこで幻聴が始まり後ろまで引きずる |
| 3. レコーダーを話し手の近くに置く | 机の中央に。資料や書類の上に置かない（紙の音を拾う） |
| 4. 空調やプロジェクタから離す | 連続した雑音があると声との差が詰まる |

**2 は今日から無料でできて、効果も測れます。** 次の録音で最初の 10 分に警告が出なくなれば、
それが答えです。

---

## 設定を変えたくなったら

**変える前に、同じ音声で前後を比べてください。** 1 区間だけの結果で判断すると外します。
このプロジェクトでは、それで 7 回続けて間違えました（上の「効かなかったこと」がその記録です）。

既定値とその根拠は `application.properties` のコメントと `FfmProperties` の説明にあります。
すべて実測に基づいていて、思いつきで決めた値はありません。

## 用語

数値を直接見るときの対応表です。

| このメモの言い方 | 数値・設定名 |
| --- | --- |
| 10 分ごとの区間 | `part_000.txt` などの part |
| 同じ行が何回続いたか | `transcribe.ffm.repetition-warn-lines` |
| 相槌を数えない文字数 | `transcribe.ffm.repetition-min-line-length` |
| 1 秒あたり何文字拾えたか | `transcribe.ffm.min-chars-per-audio-second` |
| 無音を飛ばす設定 | VAD（`--vad` / `transcribe.ffm.vad`） |

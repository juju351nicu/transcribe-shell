# transcribe-ffm の初期プロンプトのサンプル。
#
# 使い方: このファイルをホーム直下に whisper-prompt.txt という名前でコピーし、実際の参加者名に書き換える。
#   Windows: copy docs\whisper-prompt.sample.txt %USERPROFILE%\whisper-prompt.txt
#   Mac/Linux: cp docs/whisper-prompt.sample.txt ~/whisper-prompt.txt
# 置き場所は設定 transcribe.ffm.initial-prompt-file で変えられる。
#
# なぜリポジトリに実物を置かないか: 参加者の氏名が入るため。実物は .gitignore で除外している。
#
# 仕組み: whisper は「直前に話されていた文字列」としてこれを受け取り、その語彙・文体に寄った出力をする。
# 参加者名や案件用語の取り違え（例: 姓C → （読みのみ））は、モデルサイズよりこのプロンプトの方が効く。
#
# 書き方のルール
# - # で始まる行はコメント。残りの行はそのまま連結される（行の間に空白は入らない）
# - 辞書のように単語を並べるより、欲しい出力と同じ文体（句読点・敬称あり）の短い日本語文にする
# - whisper が使うのは末尾 224 トークンまで。日本語の姓 + さん + 、で 4〜5 トークン
# - ただし人数が多いと 1 人あたりの効きが薄まる。2026-09-06 の実測では、2 名の短い文に比べて
#   43 名全員（215 トークン）を入れた方が成績が落ちた。その会議に出る人だけ、10 人前後に絞る
# - 末尾ほど音声に近いので、よく発言する人を後ろに置く
# - 読みが珍しい名前は「姓F（いがらし）さん」のように読みを添える。ただし読みを添えても
#   漢字にならず音だけ拾うことがある（実測）
# - transcribe.ffm.carry-initial-prompt=true は勧めない。2026-09-08 の実測では固有名詞は良くなったが、
#   毎ウィンドウ前置されるこのプロンプト自体が出力に混ざり、同じ行が 42 回繰り返された
